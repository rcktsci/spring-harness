# Spec Delta: workspace-tools

## Purpose

Нативные инструменты рабочего каталога, исполняемые серверно в изолированном per-session Docker-контейнере из helper-образа (D-30): файловые операции, bash, лимиты вывода, lifecycle контейнера.

## ADDED Requirements

### Requirement: Per-session контейнер с ленивым созданием

Серверное исполнение инструментов SHALL происходить в контейнере с именем `harness-<sessionId>`, создаваемом лениво при первом вызове инструмента сессии. Workspace примонтирован bind-mount'ом хостового каталога `workspaces/sessions/{sessionId}`; lifecycle контейнера = lifecycle сессии (в M1 удаление — только рестарт-сканом осиротевших; API удаления сессий нет). Ресурсные лимиты (cpu/mem) — конфиг с дефолтами.

#### Scenario: ленивое создание

- **WHEN** сессия создаётся, но инструментов не вызывала
- **THEN** контейнер не создаётся

#### Scenario: создание при первом вызове

- **WHEN** модель впервые вызывает инструмент в сессии
- **THEN** контейнер `harness-<sessionId>` создаётся и инструмент исполняется в нём

### Requirement: Helper-образ локально

Helper-образ (минимальная ОС + find/grep/coreutils/git) SHALL собираться из Dockerfile в репозитории и присутствовать на VM локально. Pull из registry — только retry/backoff на случай обновления; недоступность registry не блокирует существующие сессии.

#### Scenario: registry недоступен

- **WHEN** registry недоступен, а образ присутствует локально
- **THEN** контейнеры создаются и инструменты работают

### Requirement: Нативные инструменты

Система SHALL предоставить инструменты: `read_file (path, offset?, limit?)`, `write_file (path, content)` → created|overwritten, `edit_file (path, oldString, newString, replaceAll?)` → ровно одно вхождение иначе `not-found`/`ambiguous`, `glob (pattern)`, `grep (pattern, include?)`, `bash (command, timeout?, cwd?)`. Все пути относительные, резолв от корня workspace; выход за пределы workspace (path traversal, `..`) запрещён.

#### Scenario: чтение файла

- **WHEN** агент вызывает read_file с относительным путём существующего файла
- **THEN** инструмент возвращает содержимое с учётом лимита вывода

#### Scenario: path traversal

- **WHEN** путь содержит `..` или указывает вне корня workspace
- **THEN** инструмент возвращает ошибку, файловая система хоста не затрагивается

#### Scenario: edit_file с неоднозначным вхождением

- **WHEN** oldString встречается в файле более одного раза и replaceAll не задан
- **THEN** инструмент возвращает ошибку `ambiguous`, файл не изменяется

### Requirement: Bash с таймаутом

`bash` SHALL исполнять команду в контейнере с таймаутом (аргумент, ограничен конфигом); stdout и stderr объединены; при превышении таймаута процесс убивается, в отчёте исполнения выставляется `timedOut: true`. Non-zero exit code — не ошибка инструмента: результат возвращается с exitCode.

#### Scenario: команда с non-zero exit

- **WHEN** bash исполняет команду, завершающуюся с кодом 3
- **THEN** инструмент возвращает вывод и exitCode=3, статус OK

#### Scenario: таймаут команды

- **WHEN** команда выполняется дольше таймаута
- **THEN** процесс убивается, результат помечен как превышение таймаута

### Requirement: Лимит вывода и единый отчёт исполнения

Вывод каждого инструмента SHALL ограничиваться конфигурируемым лимитом с маркером `truncated` при усечении. Результат инструмента — единый контракт `{ callId, tool, status: OK|ERROR|CANCELLED|LOST, output?, exitCode?, truncated?, timedOut? }` (`timedOut` — только bash).

#### Scenario: усечение большого вывода

- **WHEN** вывод bash превышает лимит
- **THEN** возвращаются первые N байтов с `truncated: true`

### Requirement: Отказы контейнера

Смерть контейнера во время вызова SHALL давать статус `LOST` с причиной. Ошибка монтирования workspace-каталога при старте контейнера SHALL давать инструменту ответ `ERROR` с причиной.

#### Scenario: контейнер умер во время bash

- **WHEN** контейнер умирает в момент исполнения команды
- **THEN** агент получает TOOL_RESULT со статусом LOST и причиной
