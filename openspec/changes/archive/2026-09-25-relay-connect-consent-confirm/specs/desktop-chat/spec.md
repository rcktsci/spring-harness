# desktop-chat Specification

## Purpose

Чат-интерфейс Web Desktop: список сессий, лента сообщений со всеми MessageKind, отправка сообщений, команды compact/stop, SSE-подписка на события сессии через fetch-stream.

## MODIFIED Requirements

### Requirement: Активная сессия и релей-статус

UI SHALL показывать статус подключения релея к активной сессии: «не подключён» / «подключён (N инструментов)» / «сессия открыта в другом месте» (4409 superseded); текст «подключён» SHALL показываться только для зарегистрированного релея — незарегистрированный релей показывает причину (отказ согласования, отказ сервера) или фазу. Кнопка «Подключить»/«Отключить» управляет регистрацией (desktop-relay-client). При открытии FREE root-сессии UI SHALL запускать авто-подключение релея (desktop-relay-client: connect + register с basePath по умолчанию) без нажатия кнопки; для STATE-сессий авто-подключение не выполняется, а строка релея показывает «релей доступен только для root-сессий» (не статус предыдущей FREE-сессии). Причина последней неудачи регистрации (отказ согласования, `workspace-occupied` и пр.) SHALL быть видна в строке релея. Диалоги согласования регистрации и подтверждения команды (D-93) SHALL быть доступны из любого view как глобальный оверлей.

#### Scenario: индикация подключения

- **WHEN** регистрация на активную сессию прошла успешно
- **THEN** показывается «подключён (N инструментов)»

#### Scenario: авто-подключение при открытии сессии

- **WHEN** пользователь открывает FREE root-сессию
- **THEN** релей автоматически подключается и регистрируется; статус в строке релея обновляется без нажатия «Подключить»

#### Scenario: отказ в согласовании виден

- **WHEN** пользователь отклонил согласование первой регистрации (или сервер отклонил регистрацию)
- **THEN** в строке релея видна причина, а не безликое «подключён»; кнопка остаётся в состоянии «Подключить»

#### Scenario: STATE-сессия показывает индикатор

- **WHEN** пользователь открывает STATE-сессию (в том числе сразу после зарегистрированной FREE-сессии)
- **THEN** строка релея показывает «релей доступен только для root-сессий», а не статус другой сессии

#### Scenario: диалог поверх любого view

- **WHEN** приходит запрос согласования или подтверждения команды, пока пользователь находится не в чате
- **THEN** диалог показывается поверх текущего view
