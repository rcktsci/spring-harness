# desktop-chat Specification

## Purpose

Чат-интерфейс Web Desktop: список сессий, лента сообщений со всеми MessageKind, отправка сообщений, команды compact/stop, SSE-подписка на события сессии через fetch-stream.

## MODIFIED Requirements

### Requirement: Список сессий

UI SHALL показывать список FREE-сессий (`GET /api/v1/sessions?mine=true`): заголовок, агент, `runtimeStatus`-бейдж (IDLE / TURN_RUNNING / PARKED_ASYNC; `PARKED_CLIENT` — зарезервирован и не присваивается, D-84 — UI его не обрабатывает), время активности (превью последнего сообщения НЕ показывается — SessionDto его не содержит, отдельный запрос на каждую сессию — несоразмерно); сортировка по `lastActivityAt`; поле поиска в шапке списка (debounce 300 мс → `q=`); пагинация курсором. Создание новой сессии (`POST /api/v1/sessions`) — выбор агента из каталога (`GET /api/v1/agents`), заголовок. Каталог агентов SHALL загружаться при монтировании и перезагружаться при обновлении списка; сбой загрузки каталога SHALL отличаться от реально пустого каталога: показывается сообщение об ошибке (в стиле ошибок списка), а пустой каталог не выдаётся за «агентов нет».

#### Scenario: открытие приложения

- **WHEN** пользователь залогинился
- **THEN** показывается список его сессий с актуальными runtimeStatus

#### Scenario: создание сессии

- **WHEN** пользователь нажимает «Новая сессия» и выбирает агента
- **THEN** создаётся FREE-сессия, открывается пустой чат

#### Scenario: сбой каталога виден

- **WHEN** `GET /api/v1/agents` не удался (401, рестарт бэкенда, сеть)
- **THEN** показывается сообщение об ошибке; «не загрузилось» не изображается как пустой каталог

#### Scenario: обновление перезагружает каталог

- **WHEN** пользователь обновляет список после восстановления бэкенда
- **THEN** каталог агентов загружается заново и ошибка исчезает
