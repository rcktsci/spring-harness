# desktop-shell Specification

## Purpose

Electron main-process приложения Web Desktop: окно, меню/tray, SSO-логин через Keycloak с безопасным хранением JWT, конфиг сервера, lifecycle и координация подсистем (relay-клиент, SSE-подписки, IPC к renderer).

## ADDED Requirements

### Requirement: Уведомление о потере сессии

При непроизвольной терминальной потере сессии (отказ гранта Keycloak при silent refresh, отсутствие refresh-токена, нечитаемое хранилище) main SHALL уведомлять renderer по типизированному IPC-мосту (`auth:session-lost`). Renderer SHALL по событию обновлять состояние store'а авторизации; если сессия не восстановима — выполнять переход на `/login` из любого view. Повторные события SHALL быть идемпотентными (переход не выполняется, если уже на `/login`; циклы редиректов и лавины при параллельных 401 — исключены). Интерактивный выход (Sign out) событие не порождает — его переход уже реализован в точке выхода. Временные ошибки обновления (сеть, 5xx) событие не порождают: сессия сохраняется, повтор обновления — на следующем запросе. Смена конфигурации Keycloak-параметров (issuer, clientId), делающая сохранённую сессию невалидной, SHALL обрабатываться так же: main очищает токены и рассылает `auth:session-lost`, renderer приводит UI к экрану логина. Неключевые настройки (тема, лимиты, `confirmCommands`, `showTray`, размеры окна, `baseUrl`) событие не порождают.

#### Scenario: потеря сессии из чата

- **WHEN** REST/WS-вызов получает 401, silent refresh получает отказ гранта и main очищает токены
- **THEN** renderer получает `auth:session-lost`, стор становится `loggedIn: false`, приложение переходит на `/login`

#### Scenario: повторное событие без цикла

- **WHEN** событие потери приходит повторно, пока пользователь уже на `/login`
- **THEN** состояние store'а обновляется, переход не выполняется повторно; цикла редиректов нет

#### Scenario: транзиентный исход не выкидывает

- **WHEN** refresh не удался из-за сети/5xx (токены сохранены)
- **THEN** событие потери не отправляется; пользователь остаётся в текущем view; следующий запрос снова пробует обновление

#### Scenario: интерактивный выход не дублируется

- **WHEN** пользователь выполняет Sign out из Settings
- **THEN** событие `auth:session-lost` не отправляется; переход на `/login` выполняется существующим путём Settings

#### Scenario: смена issuer инвалидирует сессию

- **WHEN** пользователь сохраняет в Settings новый Keycloak issuer
- **THEN** main очищает токены и рассылает `auth:session-lost`; renderer переходит на `/login`

#### Scenario: неключевая настройка не инвалидировала сессию

- **WHEN** пользователь меняет тему/`confirmCommands`/`showTray` и сохраняет
- **THEN** переход на `/login` не выполняется, сессия остаётся активной
