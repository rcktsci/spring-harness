## Why

Живой прогон на VM (main.log, 2026-09-25): в `10:46:58.303` и `10:46:58.326` — два `silent refresh succeeded` за 23 мс, то есть два параллельных `refreshIfNeeded` ушли с одним refresh-токеном. При ротации refresh-токенов (дефолт Keycloak «Revoke Refresh Token») второй вызов использовал уже отозванный токен → `invalid_grant` → HTTP 400 → `silent refresh failed; clearing session` → пользователь выкинут на `/login`, следующий прогон упал «no agents in catalog» (сессия стёрта). На старте приложения параллельных вызовов много (список сессий, каталог агентов, SSE, relay auto-register, артефакты) — гонка воспроизводится стабильно.

Плюс смежная гигиена: `refreshIfNeeded` стирает сессию при **любой** ошибке обновления — включая сетевой сбой и 5xx. Кратковременная недоступность сети логинит пользователя заново. В тексте ошибки refresh-вызова только код статуса — тела ответа Keycloak нет, диагностика слепая.

## What Changes

- **Single-flight**: параллельные `refreshIfNeeded`/`requireAccessToken` на истёкшем токене ждут **один** сетевой refresh; in-flight обещание живёт на уровне модуля `auth.ts`, сбрасывается при settle (включая ошибку); все ожидающие получают одинаковый результат (новый access token либо «нет токена»); очистка токенов при неудаче — ровно один раз.
- **Разделение исходов refresh**: отказ гранта Keycloak (HTTP 4xx на token endpoint — грант недействителен/отозван) → сессия завершается, токены чистятся; временная ошибка (сеть, 5xx, кривой 2xx-ответ) → токены **сохраняются**, вызов возвращает «нет токена», следующий запрос попробует обновиться снова. Поведение гейта `isSessionUsable` не меняется.
- **Диагностика**: текст ошибки refresh-вызова включает причину от Keycloak (тело ответа, где живёт `invalid_grant`/описание), не только код статуса.

## Capabilities

### Modified Capabilities

- `desktop-shell` — «SSO-логин и хранение токена»: single-flight на silent refresh; refresh-отказ делится на терминальный (грант отозван → выход на логин) и временный (сеть/5xx → токены сохраняются, повторная попытка при следующем запросе).

### New Capabilities

Нет.

## Impact

- **Код**: `web-desktop/src/main/auth.ts` (single-flight, классификация исходов, тело ошибки) — единственный файл.
- **Тесты**: новый `tests/unit/auth-refresh.test.ts` (single-flight happy-path, отказ гранта, временные ошибки, сброс in-flight, отсутствие лишних fetch на свежем токене).
- **Backend**: без изменений; контракты api-contracts не затрагиваются (клиентский SSO-флоу).
- **Числовые параметры**: новых нет (clock skew и прочее — уже конфиг).

## Non-goals

- Упреждающий (proactive) refresh по таймеру до истечения access-токена.
- Retry-циклы refresh с backoff внутри `refreshIfNeeded`.
- Изменение серверного/Keycloak конфига (ротация refresh-токенов остаётся включённой).
