# desktop-shell Specification

## Purpose

Electron main-process приложения Web Desktop: окно, меню/tray, SSO-логин через Keycloak с безопасным хранением JWT, конфиг сервера, lifecycle и координация подсистем (relay-клиент, SSE-подписки, IPC к renderer).

## MODIFIED Requirements

### Requirement: SSO-логин и хранение токена

Приложение SHALL реализовать Keycloak OAuth2 Authorization Code + PKCE: открытие **видимого** `BrowserWindow` с URL авторизации (из конфига — пользователь видит форму Keycloak и вводит креды), перехват redirect на localhost-loopback, обмен кода на JWT, закрытие окна после redirect. Полученные access/refresh-токены SHALL храниться через `safeStorage` (OS keychain); если safeStorage недоступен (нет keychain на ОС/окружении) — отказ с понятным сообщением (plain-text хранение токенов запрещено). При истечении access-токена — silent refresh (без окна, fetch code exchange); при отказе refresh — возврат на экран логина. Выход (Logout) — очистка хранилища + open redirect logout Keycloak. Параллельные запросы на обновление SHALL координироваться (single-flight): на пачку одновременных вызовов выполняется ровно один сетевой refresh, все ожидающие получают одинаковый результат, очистка токенов при неудаче — не более одного раза на пачку; in-flight обновление сбрасывается после завершения (успех или ошибка). Исход refresh SHALL делиться на два класса: отказ гранта Keycloak (HTTP 4xx token endpoint, кроме retry-later кодов 408/429, которые относятся к временным) — терминальный (токены очищаются, сессия завершается); временная ошибка (сеть, 5xx, 408/429, аномальный 2xx) — токены сохраняются, вызов возвращает «нет токена», следующий запрос повторяет обновление. Результат refresh, завершившийся после явной смены сессии (logout, смена сервера/issuer), SHALL отбрасываться: токены не сохраняются, ожидающие не получают access token, сессия остаётся завершённой. Текст ошибки обновления SHALL содержать причину от Keycloak (тело ответа) в санитизированном виде: под ключами с `token`/`secret`/`password`/`credential` в имени маскируется значение целиком (любая глубина и тип, включая поддеревья-контейнеры), имена полей сохраняются; JWT-подобные подстроки в не-JSON телах не логируются; длина тела ограничена; тело ошибки обмена кода на токен проходит ту же санитизацию.

#### Scenario: логин

- **WHEN** пользователь нажимает «Войти» и проходит Keycloak-авторизацию
- **THEN** приложение получает JWT, сохраняет его в safeStorage, открывает главный вид

#### Scenario: истёк access-токен

- **WHEN** REST/WS-вызов падает с 401
- **THEN** приложение делает silent refresh; при успехе — повтор запроса; при отказе гранта — экран логина

#### Scenario: logout

- **WHEN** пользователь выбирает Logout
- **THEN** токены удаляются из safeStorage, открывается Keycloak logout URL, приложение возвращается на экран логина

#### Scenario: пачка параллельных запросов на истёкшем токене

- **WHEN** несколько потребителей одновременно требуют access-токен, а он истёк
- **THEN** к token endpoint уходит ровно один refresh-вызов; все ожидающие получают один и тот же новый access token; сохранение токенов — один раз

#### Scenario: ротация refresh-токена не ломает сессию

- **WHEN** параллельный refresh использует уже отозванный токен (Keycloak вернул 4xx `invalid_grant`)
- **THEN** токены очищаются ровно один раз, все ожидающие получают отказ, сессия завершается на экране логина; в логе — причина от Keycloak

#### Scenario: временная ошибка не логинит заново

- **WHEN** refresh падает из-за сети или 5xx
- **THEN** токены сохраняются; ожидающие получают «нет токена»; следующий запрос снова пробует обновление (in-flight сброшен)

#### Scenario: повторная пачка после ошибки

- **WHEN** предыдущая пачка обновления завершилась ошибкой и приходит новый запрос токена
- **THEN** выполняется новый сетевой refresh (in-flight не залипает)

#### Scenario: logout во время обновления

- **WHEN** пользователь выходит из сессии, пока in-flight refresh ещё не завершился
- **THEN** результат refresh отбрасывается: токены не записываются обратно, ожидающие не получают access token, сессия остаётся завершённой (не залогинен)

#### Scenario: rate limit не логинит заново

- **WHEN** token endpoint отвечает 429 (или 408)
- **THEN** исход временный: токены сохраняются, повтор обновления на следующем запросе
