# Spec Delta: llm-gateway

## Purpose

Единая точка обращения к LLM-провайдерам: клиент модели собирается из БД-конфигурации (учётные данные + параметры модели), стриминг ответов с возможностью отмены, ретраи на временные ошибки.

## ADDED Requirements

### Requirement: Клиент модели из БД-конфигурации

Клиент модели SHALL собираться из записи модели (OpenAI-совместимый `base_url`, `model_id`, параметры) и связанной записи учётных данных (api_key расшифровывается на стороне приложения с учётом версии ключа). Автоконфигурация заготовленных клиентов не используется — один и тот же запрос к разным моделям идёт по их собственным настройкам.

#### Scenario: две модели с разными base_url

- **WHEN** агенты двух сессий ссылаются на разные записи моделей
- **THEN** запросы каждой сессии идут к её `base_url` с её `model_id` и api_key

#### Scenario: отсутствие учётных данных

- **WHEN** запись модели ссылается на несуществующие учётные данные
- **THEN** старт процесса проходит штатно; Turn, обратившийся к такой модели, завершается FAILED с SYSTEM-событием причины в журнале сессии

### Requirement: Стриминг ответа

Ответ модели SHALL доставляться потребителю по мере генерации (поток deltas), без ожидания полного ответа. Завершённый ответ фиксируется в журнале сессии целиком.

#### Scenario: потоковая доставка

- **WHEN** модель генерирует ответ
- **THEN** подписчик потока сессии наблюдает наращивание ответа до его завершения

### Requirement: Отмена генерации

Инициированная генерация SHALL быть отменяемой: после отмены поток прекращается, следующий вызов модели в этом Turn'е не производится.

#### Scenario: отмена во время генерации

- **WHEN** на активном Turn'е запрошена отмена (stop) во время стрима
- **THEN** стрим прекращается, Turn завершается со статусом CANCELLED

### Requirement: Ретраи временных ошибок

Ошибки 429/5xx SHALL повторяться с экспоненциальным backoff; число попыток — конфиг. После исчерпания попыток Turn завершается со статусом FAILED: в журнал сессии дописывается SYSTEM-событие с причиной, `last_consumed_seq` доводится до `last_seq` (см. agent-turn «Агентный цикл»); частичный/неиспользованный результат не фиксируется как ответ ассистента; автоматический повтор Turn'а не производится.

#### Scenario: 429 с последующим успехом

- **WHEN** первый вызов возвращает 429, повтор через backoff — успех
- **THEN** Turn продолжается штатно, пользователь не видит ошибки

#### Scenario: исчерпание попыток

- **WHEN** все попытки исчерпаны ошибками 429/5xx
- **THEN** Turn завершается со статусом FAILED, ошибка зафиксирована в журнале

### Requirement: Учёт токенов

При наличии у провайдера данных usage система SHALL фиксировать счётчик токенов ответа в соответствующем событии сессии.

#### Scenario: провайдер вернул usage

- **WHEN** ответ модели завершён и провайдер передал usage
- **THEN** в событии ASSISTANT заполнено поле tokens
