# desktop-chat Specification

## Purpose

Чат-интерфейс Web Desktop: список сессий, лента сообщений со всеми MessageKind, отправка сообщений, команды compact/stop, SSE-подписка на события сессии через fetch-stream.

## ADDED Requirements

### Requirement: Список сессий

UI SHALL показывать список FREE-сессий (`GET /api/v1/sessions?mine=true`): заголовок, агент, `runtimeStatus`-бейдж (IDLE / TURN_RUNNING / PARKED_ASYNC), последнее сообщение, время активности; сортировка по `lastActivityAt`; поиск по `q=`; пагинация курсором. Создание новой сессии (`POST /api/v1/sessions`) — выбор агента из каталога (`GET /api/v1/agents`), заголовок.

#### Scenario: открытие приложения

- **WHEN** пользователь залогинился
- **THEN** показывается список его сессий с актуальными runtimeStatus

#### Scenario: создание сессии

- **WHEN** пользователь нажимает «Новая сессия» и выбирает агента
- **THEN** создаётся FREE-сессия, открывается пустой чат

### Requirement: Лента сообщений

UI SHALL отображать сообщения (`GET /api/v1/sessions/{id}/messages`) в хронологическом порядке: USER (справа, автор), ASSISTANT (слева, markdown-рендер), SYSTEM (центр, приглушённый), TOOL_CALL (сворачиваемый: инструмент + args), TOOL_RESULT (сворачиваемый: статус OK/ERROR/CANCELLED/LOST, output, exitCode, `truncated`-маркер), COMPACT (граница раунда), ASYNC_ACCEPTED (плейсхолдер «ожидает результат»), поздние результаты — с `late`-маркером. Подгрузка более ранних сообщений по курсору при скролле вверх.

#### Scenario: ассистент ответил

- **WHEN** оркестратор отвечает текстом
- **THEN** сообщение рендерится слева с markdown

#### Scenario: инструмент вызван

- **WHEN** в ленте TOOL_CALL + TOOL_RESULT
- **THEN** отображается сворачиваемый блок с инструментом, args и результатом

#### Scenario: async-плейсхолдер

- **WHEN** инструмент превысил окно и пришёл ASYNC_ACCEPTED
- **THEN** показывается плейсхолдер; поздний TOOL_RESULT заменяет его на результат с late-маркером

### Requirement: Отправка и команды

UI SHALL отправлять сообщения (`POST /api/v1/sessions/{id}/messages`) с атрибуцией автора; команды: `/compact` → `POST .../compact`, `/stop` → `POST .../stop` (с подтверждением «остановить Turn?» при активном TURN_RUNNING). Ввод во время TURN_RUNNING — разрешён (событие подхватится доп. раундом; индикатор «агент работает»).

#### Scenario: отправка сообщения

- **WHEN** пользователь пишет текст и нажимает Enter
- **THEN** сообщение отправляется, появляется в ленте

#### Scenario: остановка

- **WHEN** пользователь нажимает Stop во время TURN_RUNNING
- **THEN** отправляется stop-команда, лента показывает CANCELLED-результаты по завершении

### Requirement: SSE-подписка через fetch-stream

UI SHALL подписываться на события сессии через `fetch` + `ReadableStream` (EventSource не поддерживает Bearer-заголовок — D-87): `message.created`, `session.status` (обновление runtimeStatus-бейджа и индикатора), обработка `retry`-интервала и реконнекта по Last-Event-ID. При переключении сессии — отписка старой, подписка новой.

#### Scenario: новое сообщение в фоне

- **WHEN** сессия активна и пришёл message.created
- **THEN** сообщение добавляется в ленту без перезагрузки

#### Scenario: статус сменился

- **WHEN** приходит session.status с TURN_RUNNING
- **THEN** бейдж сессии и индикатор ввода обновляются

#### Scenario: реконнект

- **WHEN** stream-соединение рвётся
- **THEN** клиент переподключается с Last-Event-ID без пропусков и дублей

### Requirement: Активная сессия и релей-статус

UI SHALL показывать статус подключения релея к активной сессии: «не подключён» / «подключён (N инструментов)» / «сессия открыта в другом месте» (4409 superseded); кнопка «Подключить»/«Отключить» управляет регистрацией (desktop-relay-client).

#### Scenario: индикация подключения

- **WHEN** регистрация на активную сессию прошла успешно
- **THEN** показывается «подключён, инструменты: bash, read_file, …»
