# workspace-artifacts Specification

## Purpose

Просмотр и скачивание файлов серверного workspace сессии в Web Desktop (`GET /api/v1/sessions/{id}/workspace/files`, api-contracts §8): браузер файлов, save-as, open-in-OS.

## ADDED Requirements

### Requirement: Браузер файлов workspace

UI SHALL отображать файлы серверного workspace активной сессии: список (имя, размер, изменение) с навигацией по подкаталогам; рефреш. Запросы идут через существующий REST-эндпоинт скачивания (для каталогов — клиентская навигация, сервер отдаёт только файлы).

#### Scenario: открытие браузера

- **WHEN** пользователь открывает вкладку «Артефакты» активной сессии
- **THEN** показывается список файлов корня workspace

#### Scenario: подкаталог

- **WHEN** пользователь открывает подкаталог
- **THEN** показывается его содержимое

### Requirement: Скачивание и открытие

Пользователь SHALL скачивать выбранный файл (save-as диалог ОС) или открывать его в приложении ОС по умолчанию (временная копия в `userData/cache/` с тем же именем). Серверные 422 `path-invalid`/`extension-not-allowed` и 413 `payload-too-large` показываются понятными сообщениями.

#### Scenario: save-as

- **WHEN** пользователь выбирает «Сохранить как…»
- **THEN** файл скачивается стримом в выбранное место

#### Scenario: открыть в ОС

- **WHEN** пользователь выбирает «Открыть»
- **THEN** файл копируется во временный каталог и открывается приложением по умолчанию

#### Scenario: бинарник не разрешён

- **WHEN** сервер отвечает 422 extension-not-allowed
- **THEN** показывается сообщение «этот тип файла нельзя открыть/скачать»
