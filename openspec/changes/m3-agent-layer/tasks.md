Verify: integration — рестарт посреди async → LOST, повторный скан без дублей (AsyncToolTurnTest).
- [x] N.4 `message.created` → сессионный wake (через existing `InMemorySessionEventBroadcaster`). Поле `MessageDto.late` (boolean) — в спеке уже зарезервировано, регенерация не потребовалась; маппер заполняет из payload. Adдитивно, без BREAKING. WireMock-LLM тест на `late=true` (AsyncLateResultApiTest). Mini-amendment openapi.yaml (фикс ревью N-1): `MessageKind` += `ASYNC_ACCEPTED`, регенерация, фильтры из API удалены — плейсхолдер виден клиентам как обычное событие сессии.
- [x] N.5 `AgentTurnEngine` обновлён — write-ahead раунда учитывает placeholder: TOOL_CALL всегда write-ahead (M1, execution-model §1: журнал — маркер «в полёте», крах окна закрывает рестарт-скан); `ASYNC_ACCEPTED` дописывается отдельной строкой после round-finish с async-вызовом (D-60). Порядок «плейсхолдер прежде позднего результата» гарантирует sess-лок (D-64); «первый финальный выигрывает» закрывает гонки без атомарной пары. Замена исходной формулировки «одна транзакция» (фикс ревью N-3): буквальная атомарная пара ломала write-ahead-инвариант и observable-семантику журнала; цель задачи (нет дублей при kill) достигается. Verify: integration — kill посреди записи → рестарт-скан не дублирует (повторный restartScan — ровно один LOST).
- [x] N.6 `agent/AsyncTimeoutWatcher` — ShedLock-джоба (расписание `harness.late-result.watch-schedule`, лок `async-timeout-watcher` с TTL `harness.late-result.timeout.ttl`): сканирует `session_message` где `kind='ASYNC_ACCEPTED'` и нет парного финального TOOL_RESULT (`OK|ERROR|CANCELLED|LOST`); если `created_at < now() - harness.late-result.timeout-ms` (конфиг, дефолт 900000 = 15 мин) → синтетический TOOL_RESULT LOST под программным локом сессии `sess-{id}` (D-64) + wake. Verify: integration — watcher закрывает протухший вызов LOST, свежий не трогает (AsyncToolTurnTest).

## §O. Spawn + subagent-lifecycle

- [ ] O.1 `agent/SubagentSpawner` (`execution/impl/`) — `spawn(agentKey, prompt, params)` строго синхронный (блокирующий): создаёт child session с `parent_session_id = current.id`, `depth = parent.depth + 1` (колонка `session.depth`, миграция 074 / D-61); проверка `depth ≤ harness.spawn.max-depth` ДО создания (`TOOL_RESULT forbidden (depth-limit)` если превышен); запуск child Turn; родительский поток ждёт завершения субагента (условие — см. subagent-lifecycle «Завершение субагента»). Owner = current.owner. Конфиги `harness.spawn.max-depth` + `harness.spawn.workspace-strategy: inherit|new` (M3 — только inherit; new — точка эволюции). Verify: integration — happy path + depth-limit.
- [ ] O.2 Subagent-to-parent финал: блокирующий возврат — `TOOL_RESULT` (с output субагента) фиксируется на ходу родителя, где spawn вызван. Если родительский Turn завершён до возврата (отмена/рестарт) — поздний TOOL_RESULT через `message.created` → wake/новый Turn. Маппинг: исход `last_turn_outcome` субагента → TOOL_RESULT. Verify: integration — orchestrator spawn'ит, субагент работает, родитель получает output.
- [ ] O.3 `agent/SubtreeCanceller` — `POST /api/v1/sessions/{id}/stop` каскадирует по `parent_session_id` (BFS, рекурсивно). Каждой отменяемой сессии — `cancel_requested=true`; активные Turn'ы завершаются `CANCELLED`; незакрытые async — синтетический `TOOL_RESULT CANCELLED «subtree-cancelled»`. Stop идемпотентен. Verify: integration — stop с 3 уровнями → все 5 сессий CANCELLED; повторный stop → 202 без эффекта.
- [ ] O.4 `agent/ReadCompactedTool` — `read_compacted(compact_message_id)` резолвит `id → seq` по `session_message.id` только в пределах текущей сессии (id чужой сессии → `TOOL_RESULT not-found`; cross-session-чтение — вне M3, R8). Возвращает оригиналы, скрытые COMPACT-покрытием (по `covers`). Лимит `harness.compact.read-max-bytes` с маркером `truncated`. Verify: integration — компактированные сообщения возвращаются; id вне сессии → not-found.
