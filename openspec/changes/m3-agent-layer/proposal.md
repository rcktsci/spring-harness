## Why

M2 закрыл **домен задач** (workflow+ревisions, BASH/WAIT_*/STATE-сессии, capability-URL, триггеры, `transition` с гейтом D-59). Оркестратор сценариев («Сделай биллинг»: разрезать задачу, поставить подзадачи в `WAIT_TASKS`-стейджи, поймать FAILED → направить в сессию-разборщик) и роуминг-сценарий (client-side tooling) в M2 нереализуемы: агенту нельзя спавнить субагентов, читать скрытое за COMPACT, держать in-flight async-инструменты и каскадировать отмену по поддереву. M3 закрывает именно агентский слой — то, что делает одного агента **оркестратором** многих.

## What Changes

- **Async-инструменты с окном**: bash объявлен `async-capable`. Окно исполнения (конфиг) → `ASYNC_ACCEPTED(callId)` с placeholder-сообщением → фон доводит → поздний `TOOL_RESULT` с `late=true` через сессионный канал `message.created`/`session_message.seq` (M1, `InMemorySessionEventBroadcaster`; инкремент `last_seq` сессии) → wake существующим `AgentTurnEngine.run`-путём (M2 J-1: rewake + новый Turn с early-exit pending). Первый финальный результат по `call_id` выигрывает — финальные статусы `OK|ERROR|CANCELLED|LOST` (синтетические LOST/CANCELLED тоже финальные; `ASYNC_ACCEPTED` — placeholder, не финал) — дубли игнорируются.
- **`spawn_subagent(agent_key, prompt, params?)`**: строго синхронный (блокирующий) metaTool: родительский поток ждёт завершения субагента; результат — только на ходу родителя, где spawn вызван; если родительский Turn завершён до возврата (отмена/рестарт) — поздний `TOOL_RESULT` через `message.created` вызывает wake/новый Turn. Создаёт дочернюю сессию (`parent_session_id`), owner дочерней наследуется от родительской, `depth = parent.depth + 1` (колонка `session.depth`, D-61). Завершение = `«ход субагента закончен И pending_tool_calls==0»` (D-10). Лимит — конфиг `harness.spawn.max-depth` (дефолт 2), превышение → `TOOL_RESULT forbidden (limit)` (не пробрасывается как исключение).
- **`read_compacted(compact_message_id)`**: резолвит `id → seq` по `session_message.id` **в пределах текущей сессии** (cross-session-чтение — вне M3), затем возвращает оригиналы, скрытые COMPACT-событием по `covers` (D-44). В M3 видимость = весь журнал сессии без COMPACT; `read_compacted` снимает покрытие ad-hoc для указанного id (не модифицируя COMPACT-евенты).
- **Оркестратор-агент (D-38 §2b)**: агенты с `permissions_jsonb.metaTools = true` получают **все** meta-инструменты (`create_workflow`, `edit_workflow`, `create_task`, `create_subtask`, `set_dependency`, `configure_trigger`) **без** гейта D-59 (`instructionSource != USER`). Для остальных агентов D-59 остаётся: `transition` только при `USER`, остальные metaTools — запрещены.
- **MCP-клиент (D-21)**: `McpClientConfig` агента (`tools_jsonb.mcp[servers]`) — список MCP-серверов (+ `include`/`exclude` фильтры инструментов). Конфиг в `application.yml` — глобальный пул MCP-серверов с auth через корпоративный SSO-прокси (как данные не храним). Токены обновляет прокси — агент про OAuth не знает. Manifest инструментов сервера включается в tool-declarations модели как обычные функции.
- **`stop_subtree` (пользовательский, не metaTool)**: отмена сессии → каскад по `parent_session_id` (все уровни вложенности). Незакрытые async у отменённых — синтетический `TOOL_RESULT CANCELLED`. Субагент отменён → родитель получает `TOOL_RESULT` «subtree-cancelled» и решает.
- **Расширение рестарт-скана**: на старте процесса — закрытие `TOOL_CALL` без парного `TOOL_RESULT` **у субагентских сессий** (уже есть для обычных) + orphan-container cleanup для субагентских контейнеров (если у субагента есть свой workspace-биндинг — отдельный контейнер `harness-<subSessionId>`).
- **Тримминг сессии (sync-deepening для оркестратора)**: orchestrator-сессия спавнит субагентов; субагент-сессии — STATE-сессии тех же задач (через `create_subtask` + вход в AGENT-state ребёнка). Приём: субагентская сессия создаётся ровно когда родительская задача входит в нужный AGENT-state (через тот же `StateSessionService.findOrCreate` M2 J.1).
- **Без новых таблиц**; 2 узких миграции: `074_create_column_session_depth.xml` (`session.depth NOT NULL DEFAULT 0`, D-61) и `075_alter_session_message_kind_add_async_accepted.xml` (расширение `MessageKind` значением `ASYNC_ACCEPTED`, D-60). Остальные поля/индексы уже есть (`session.parent_session_id`, `llm_model.params_jsonb`, `agent.tools_jsonb`, `agent.permissions_jsonb`, `task.transition_history` для каскада).
- **API (аддитивно, без BREAKING)**: `MessageDto.late` (уже есть в спеке M1) становится реальным полем в M3 (в M1 было зарезервировано «отсутствует»). Без bump версии.

## Capabilities

### New Capabilities
- `async-instruments`: окно инструмента → `ASYNC_ACCEPTED(callId)` → поздний `TOOL_RESULT` через сессионный канал `message.created` (`session_message.seq`, M1); первый финальный выигрывает (`OK|ERROR|CANCELLED|LOST`); рестарт-скан + `AsyncTimeoutWatcher` закрывают долгие вызовы LOST-синтетикой.
- `subagent-lifecycle`: `spawn_subagent` (строго синхронный — блокирующий, с лимитом `harness.spawn.max-depth`); `parent_session_id` каскад при отмене; ownership наследование; `read_compacted` через `covers` (same-session id→seq резолв).
- `orchestrator-meta-tools`: metaTool-каталог для оркестраторов (`create_workflow`/`edit_workflow`/`create_task`/`create_subtask`/`set_dependency`/`configure_trigger`); гейт `metaTools = permissions_jsonb.metaTools == true` (D-38 §2b) — **снимает** D-59 для оркестратора, оставляет для обычных.
- `mcp-client`: Spring AI MCP client интеграция; `tools_jsonb.mcp[servers]` агента с include/exclude; глобальный `harness.mcp.servers` в `application.yml`; SSO-прокси для auth (токены — у прокси).

### Modified Capabilities
- `agent-turn`: расширение цикла — async-окно, `ASYNC_ACCEPTED` (новое значение `MessageKind`), late TOOL_RESULT, wake по сессионному каналу `message.created` (M1); новый metaTool `spawn_subagent`; новый metaTool `read_compacted`; гейт metaTools расширен оркестраторским путём; write-ahead раунда учитывает placeholder (атомарная запись TOOL_CALL+ASYNC_ACCEPTED до фактического TOOL_RESULT).
- `session-api`: `MessageDto.late` поле — из спеки M1 «отсутствует» переходит в реальное (boolean, в TOOL_RESULT/SYSTEM). Это аддитивно, без bump версии.

## Impact

- **Код**: новые пакеты `agent/` (orchestrator, subagent, async-runtime); `mcp/` (клиент, манифест); `common/` расширен (`LateToolResultPublisher`, `CoversResolver` для id→seq); `execution/AgentTurnEngine` + `WorkspaceTools` расширены (async bash путь); `lifecycle/SubtreeCanceller` (каскад stop по `parent_session_id`); `integration/mcp` — конфиг-биндинг через Spring AI MCP client.
- **API**: 0 новых операций (новые поведения — metaTools и event-канал, существующие). `MessageDto.late` аддитивно.
- **БД**: 0 новых таблиц; 2 миграции: `074_create_column_session_depth.xml` (`session.depth INT NOT NULL DEFAULT 0`, D-61) и `075_alter_session_message_kind_add_async_accepted.xml` (ALTER CHECK `ck_session_message__kind`: + `ASYNC_ACCEPTED`, D-60/D-65).
- **Конфиг**: `harness.async.window.default-ms: 30000` (D-09); `harness.spawn.max-depth: 2`; `harness.spawn.workspace-strategy: inherit`; `harness.mcp.servers[*]` (список с url+auth, `harness.mcp.auth.proxy-url`); `harness.late-result.timeout-ms: 900000` (15 минут верхняя граница для late-tool-result, обходится `AsyncTimeoutWatcher`).
- **Стек**: зависимости — `spring-ai-mcp-client` (Spring AI BOM уже подключён в M1). Никаких новых внешних.
- **Команда**: подзадачи оркестратора (`create_subtask`) + `set_dependency` (одна операция — пачка штук) уже есть в M2 K.3 — переиспользуются.
- **Критерий M3 (roadmap)**: сценарий «Сделай биллинг» — `AcceptanceMakeBillingTest`: alice → orchestrator-сессия (FREE на ревизии `make-billing`) → сообщение «Сделай биллинг: ...» → оркестратор через `create_task` создаёт root + `create_subtask`/`set_dependency` для подзадач (analytics, contract-first, impl-module-1, impl-module-2, tests, e2e) → STAGE через `WAIT_TASKS` (подзадачи группами); упавшая analytics → ERROR в родительской сессии-разборщике; завершение → SUCCESS. Тест с живым Keycloak + WireMock-LLM (`bash` async реально стартует в контейнере, late-tool-result имитируется WireMock-задержкой).
- **Вне M3**: раннеры (control/execution split), селективная компакция (агентская поверх COMPACT), MCP-сервер наружу (D-21 reverse), ротация capability-секретов, multi-instance, WebUI/CLI/M4 — закладки эволюции.
