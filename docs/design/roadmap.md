# Дорожная карта spring-harness

> Фазы = вертикальные срезы; каждая — отдельный openspec-change (`/opsx:propose`) со ссылками на дизайн-доки. Правило приёмки фазы: интеграционные тесты (Testcontainers Postgres + WireMock LLM/MCP) + ревью субагентами по корпоративному циклу.

## M1 — Ядро сессий (фундамент)

**Объём**: identity (Keycloak-синхронизация users/groups, AccessPolicy-каркас), `SessionStore` (append-only, рендер видимости), `LlmGateway` (ChatModel из LlmModel, стриминг, отмена), агентный цикл (sync-инструменты), helper-образ + docker-java + `ContainerWorkspaceTools` (per-session контейнеры — D-30), TurnManager (wake EVENT+POLL, CAS-локи, TTL), REST/SSE сессий-сообщений, страховочная компакция, билеты, **минимальный attach (стриминг + отправка)**, **bootstrap-сид** (первые llm_credentials/agent — админ-команда CLI из env; см. architecture §4).
**Критерий готовности**: FREE-сессия через минимальный attach работает end-to-end: сообщение → модель → инструменты **в helper-контейнере** → стриминг; рестарт сервера не теряет сессии; контейнер сессии поднимается/уничтожается корректно; bootstrap-сид разворачивает профиль+агента с нуля.

## M2 — Workflow-движок

**Объём**: `WorkflowRegistry` + валидация графов, задачи (пин ревизии, `task_transition_history`, статус-проекции), STATE-сессии (уникальность пары, резюм), **минимальный мета-инструмент `transition` (обязательный reason)**, системные состояния BASH_SCRIPT / WAIT_WEBHOOK (stateless) / WAIT_TASKS (scope-выражения, теги, зависимости, цикл-валидация), подзадачи и `blocked_by`, REST+SSE задач.
**Критерий**: сценарий «двухфазное ревью с возвратом» на тестовом графе проходит (агент переводит задачу инструментом `transition`), включая таймауты и error-пути bash-состояний.

## M3 — Агентский слой

**Объём**: ревизии агентов + llm-профили, `spawn_subagent` + `read_compacted`, async-инструменты (окно, плейсхолдер, поздние результаты, рестарт-скан, LOST-контур контейнеров), отмена-поддерево, оркестратор-агент (инструменты §2b agent-tools), триггеры + вебхук-эндпоинты.
**Критерий**: сценарий «Сделай биллинг» (оркестратор режет на подзадачи, стейджи WAIT_TASKS, ревью-цикл) на CI-стенде.

## M4 — Клиенты и релей

**Объём**: attach-CLI полный (tree/inject/stop/fork/rewind/compact, задачи), CLIENT_EXEC-релей (WS-протокол, register/tool.call/result/cancel, PARKED_CLIENT), скачивание workspace-файлов.
**Критерий**: роуминг-сценарий: одна сессия, два «офиса», git pull, продолжение работы; CLIENT_EXEC-состояние ждёт исполнителя и переживает его переподключение.

## M5 — WebUI (позже)

Чат-интерфейс, дерево сессий/задач, скачивание артефактов, проваливание в субагентов. Контракт уже готов (`api-contracts.md`), WebUI — чистый потребитель.

## Эволюция (не фазы, закладки)

Раннеры (вынос TurnManager), селективная компакция (агентский инструмент поверх COMPACT), MCP-сервер наружу, ротация capability-секретов, адаптеры задач в Jira/Trello/GitLab, multi-instance состояния.
