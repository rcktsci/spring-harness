# Журнал решений spring-harness (ADR)

> Формат: решение → отвергнутые альтернативы → обоснование. Дополняется по ходу проекта.

| # | Дата | Решение | Альтернативы | Почему так |
|---|---|---|---|---|
| D-01 | 2026-09-16 | Модульный монолит с контрактами | Control/execution-раннеры (Paperclip-стиль); событийное ядро на Postgres | Простейшая эксплуатация на 50 чел; эволюция в раннеры — без смены контрактов; event-sourcing везде — YAGNI |
| D-02 | 2026-09-16 | Сессии: 2 таблицы, append-only, строки не мутируют никогда | Плоская история с UPDATE; дерево сообщений (Pi-style) | Событийный поток = durable-очередь, аудит, fork/rewind stability; дерево усложняет схему и рендер без сценариев |
| D-03 | 2026-09-16 | Гибридный wake: EVENT-tryStart + POLL раз в ~5с (ShedLock) | Чистый поллинг; чистый event-driven | Поллинг — страховка от потерь, события — латентность; так делают OpenCode и Paperclip |
| D-04 | 2026-09-16 | Нет таблицы Turn/Run: локи в колонках сессии (CAS + TTL), отмена — bool-флаг | Таблица run (recovery/audit/отмена) | LockAtMostFor и TTL закрывают recovery; отмена — флаг; аудит попыток — не сценарий заказчика (правило: сущность без сценария не существует) |
| D-05 | 2026-09-16 | Вебхуки stateless capability-URL: `POST /api/webhooks/{kind}/{id}/{token}` (`token = HMAC(secret, kind:id)`), для задач без таблицы | Таблица webhook_wait; подпись тела+timestamp (отправитель не владеет секретом) | Связь видна из current_state; проверка — чистая функция; уточнено в D-26 |
| D-06 | 2026-09-16 | Граф: последовательный с циклами; fan-out запрещён | Multi-instance состояния; BPMN fork/join | Семантика завершения веток и пустые каталоги — реальная сложность; оркестратор-LLM надёжнее генерирует простые графы; параллелизм — подзадачами и субагентами |
| D-07 | 2026-09-16 | Состояние = одна активная сессия с одним агентом; поле-список с валидацией length==1 | Состояния с N сессиями | Инвариант задачи и локов; дверь к multi-instance не закрыта |
| D-08 | 2026-09-16 | Отмена: stop(session) = цель + всё поддерево; сессии резюмируемы | Полный каскад от корня; поимённая гранулярность (TaskStop/close_agent) | Формула заказчика; открытый код opencode глушит всех — неудобно; гранулярность — надстройка потом |
| D-09 | 2026-09-16 | Async-инструменты: окно 30с → `ASYNC_ACCEPTED` → поздний TOOL_RESULT (call_id) | Всегда синхронные; поллинг статусов | Паттерн Claude Code; wake-механизм переиспользуется без новых сущностей |
| D-10 | 2026-09-16 | spawn_subagent синхронный; завершение = «ход окончен И pending_tool_calls==0» | Async-spawn; завершение по концу хода | Ложное завершение при async внутри субагента; маркер pending — тот же предикат, что рестарт-скан |
| D-11 | 2026-09-16 | Workspace: SERVER_DIR(auto/explicit) + CLIENT_EXEC; клонирование = bash-состояние подготовки | Отдельные типы REPO_CLONE и SERVER_SCRATCH | Упрощение заказчика: 2 типа вместо 4; клонирование — обычное состояние графа с ветками ошибок |
| D-12 | 2026-09-16 | Адаптеры исполнения только для нативных workspace-инструментов; остальные инструменты — MCP | Адаптеры на каждый инструмент | Роуминг-сценарий требует релея файл/bash; остальное покрывают 12+ корпоративных MCP |
| D-13 | 2026-09-16 | Вывод bash-состояний → `task_transition_history.reason` | SYSTEM-сообщение в сессию получателя перехода | «Чья сессия — до или после?» — состояние принадлежит задаче, не сессии; история переходов — честный владелец |
| D-14 | 2026-09-16 | Task-centric: автор-агент выбирает workflow; переход — инструмент агента с обязательным обоснованием | Выбор workflow задачей; свободные переходы | Жёсткие рельсы /goal; аудируемость |
| D-15 | 2026-09-16 | Шаблон/инстанс: ID/токены только в задаче; резолв выражениями; пин к ревизии | Списки ID в состояниях; мутабельные шаблоны | BPMN/Temporal-станс; правка шаблона не задевает идущие задачи |
| D-16 | 2026-09-16 | Fork/rewind — только свободным сессиям; fork = (source, seq_cutoff) | Fork задачных сессий; дерево сообщений | Целостность аудита workflow; знание из задач — export |
| D-17 | 2026-09-16 | Компакция: страховочная авто (~80% окна) + `/compact`; селективная агентская — потом; COMPACT несёт covers, строки не мутируются | Явная ошибка при переполнении; поле compacted_by у старых сообщений | Переполнение — «когда», не «если»; мутация строк ломала бы fork/rewind |
| D-18 | 2026-09-16 | Мультипользовательность с первого дня: Keycloak, группы, папки, шаринг VIEW/PARTICIPATE, атрибуция сообщений | Single-user сейчас | Общий сервер компании 50+; миграция схемы потом дороже |
| D-19 | 2026-09-16 | Клиенты: attach-CLI первым, WebUI вторым | WebUI сразу; без клиентов | Минимальный клиент — максимум пользы; WebUI — «скачать артефакт» и мониторинг |
| D-20 | 2026-09-16 | LLM: три уровня llm_credentials → llm_model → agent | Плоские поля у агента | DRY: ключи/ротация в одном месте, модели переиспользуются |
| D-21 | 2026-09-16 | MCP: только клиент в MVP; сервер наружу — позже через адаптер | Клиент+сервер | Сценария для сервера нет; REST уже интегрирует |
| D-22 | 2026-09-16 | Контракт-first везде: OpenAPI для REST, Java-интерфейсы как документы того же ранга; глоссарий обязателен; каждая сущность — с сценарием необходимости | Код-first; импровизация | Требование заказчика к процессу |
| D-23 | 2026-09-16 | Парковка Turn'а при async-вызове; 6 исчерпывающих условий выхода цикла | Таймауты на весь Turn | Детерминизм цикла; простая отладка |
| D-24 | 2026-09-16 |Wake-очередь не заводится: очередь = session_message; идемпотентность через CAS-лок | Отдельная wake-таблица | Меньше сущностей; durable by design |
| D-25 | 2026-09-16 | Триггер — сущность (`trigger`-таблица, revoke через `revoked_at`) | Хранение в params задач; отказ от триггеров | Сценарий оркестратора «внешний вебхук → задача по workflow»; отзыв должен убивать URL мгновенно |
| D-26 | 2026-09-16 | Вебхуки — capability-URL (`HMAC(secret, kind:id)` в пути) + компенсации: идемпотентность задач по построению, TLS, rate-limit, 409 вне WAIT_WEBHOOK | Подпись тела+timestamp (отправитель не владеет секретом — не работает для выдачи готового URL); GitHub-style общие секреты | Стандартный паттерн unsubscribe-ссылок; эволюция — окно действия/ротация секрета |
| D-27 | 2026-09-16 | VIEW видит сырые payload'ы (TOOL_RESULT, SYSTEM) | Редакция/маскирование | Прозрачность «смотреть, как работает субагент» — сценарий владельца; маскирование — при появлении сценария секретов |
| D-28 | 2026-09-16 | Права задач: visibility + Share(TASK) c VIEW/PARTICIPATE; STATE-сессии наследуют от задачи; workflow-ревизии — владелец или роль `harness-admin` | Отдельная RBAC-модель; «любой аутентифицированный правит шаблоны» | Унификация с сессиями/папками; запрет privilege-эскалации через графики |
| D-29 | 2026-09-16 | Suspend (флаг, Turn дорабатывает) + Stop (suspend + отмена Turn'ов + **терминал `$CANCELLED`** — псевдо-код вне codes ревизии, resume → 409) — обе операции; идемпотентность POST — хранилище `idempotency_key` (TTL 24 ч) | Одна операция; идемпотентность без хранения | Разные сценарии (пауза против аварии); контракт replay-safe требует хранения |
| D-30 | 2026-09-16 | Серверное исполнение нативных инструментов — **только через per-session Docker-контейнеры**: оркестратор в докере на выделенной VM, `/var/run/docker.sock` прокинут, управление через docker-java, свой helper-образ (минимальная ОС + find/grep/coreutils/git); контейнер `harness-<sessionId>`, workspace примонтирован томом; lifecycle = сессия | Прямое исполнение на хосте; microVM (Gondolin-style) | Изоляция 50+ пользователей на одном хосте; CC-исследование: текстовые границы не security-граница; хост остаётся чистым |
| D-31 | 2026-09-16 | Все PK — UUID v7 (кроме короткого ULID `session_message.id`); генератор — самописная реализация владельца (единая точка `IdGenerator`) | UUID v4; ULID везде | Временная сортируемость и индекс-локальность; переиспользование отшлифованной библиотеки |
| D-32 | 2026-09-16 | Делегирование прав в сессиях: эффективные права = пересечение прав владельца сессии (Keycloak-роли + гранты) и `permissions_jsonb` агента; вниз по дереву не расширяются; инструмент без прав → `TOOL_RESULT forbidden`. `harness-admin` наследуется в прямые сессии владельца | Права только у агента (эскалация: любой просит оркестратора переписать шаблоны); права только у человека (агент бессилен) | Принцип «агент не превышает полномочия принципала»; закрыта дыра инструментного пути `edit_workflow` |
| D-33 | 2026-09-16 | POLL-страховка двухуровневая: сессии (eligible) + задачи (AGENT-без-сессии → bootstrap; WAIT_* → переоценка). Outbox не заводим | Outbox-паттерн для side-effects | Все side-effects выводимы из durable-состояния дёшево индексируемыми сканами; потерянный EVENT-wake лечится POLL |
| D-34 | 2026-09-16 | Денормализации под сканы и списки: `last_seq/last_consumed_seq/message_count/tokens_total` (session), `current_state_kind/state_attempt/deadline_at` (task), partial-индексы eligible/WAIT/deadline, `share(resource)`+`group_member` lookups | Всё считать агрегатами на лету | POLL-скан и списковые API — самые горячие пути; счётчики обновляются транзакционно с дописью |
| D-35 | 2026-09-16 | LLM: bulkhead (дефолт 8 параллельных стримов) + 429/5xx → backoff×3 → парковка Turn'а; FAILED только после исчерпания | Без ограничителя (массовый отказ на утреннем пике); немедленный FAILED | Утренний пик wake × rate-limit провайдера — предсказуемая смерть без семафора |
| D-36 | 2026-09-16 | Реестр `instance` (heartbeat 10с) + scoped recovery: рестарт-скан помечает LOST только мёртвые инстансы; докатка отмен по `cancel_requested`; late-результаты — «первый финальный выигрывает»; bash-состояния требуют идемпотентных скриптов (`state_attempt`) | TTL-only кража (убивает живые Turn'ы при rolling deploy) | Правильность recovery при деплоях |
| D-37 | 2026-09-16 | Observability (см. `operations.md`): JSON-stdout логи + MDC-корреляция (instanceId/sessionId/taskId/turnId/wakeSource); маскирование capability-токенов/ключей/JWT; readiness с гистерезисом Keycloak и тумблером docker-critical; liveness — только процесс; трейсинг — MVP correlation-логи, OTel-мост opt-in с выключенным экспортёром; WAL RPO≤5мин + off-VM dump; `stop_grace_period 45s` > дренажа 30с | Файловые логи+logrotate; heap-liveness; жёсткий Keycloak-readiness; отключённый WAL; MDC-only навсегда | Контейнер-паттерны; аудит очереди ценен (RPO); деплой не должен рвать дренаж |
| D-38 | 2026-09-16 | Единая формула делегирования: эффективные права = права(owner) ∩ декларация(agent) ∩ effective(parent) ∩ права(инициатора инструкции); **гейт metaTools — только при instructionSource = USER**. Лимиты порождения: spawn.maxDepth=3 / maxChildrenPerSession=8 / maxActivePerUser=50 / per-trigger rate-cap 10/мин / тело 1МБ. Недоверенный контент: origin-маркировка + дисциплина промпта; digest-пин helper-образа; symlink-гвард; params иммутабельны после создания | Формула D-32 «owner ∩ agent» (две эскалации: вертикальная spawn metaTools-агента, горизонтальная PARTICIPANT→admin); «принципал = автор инструкции» как замена (ломает модель прокси) | STRIDE-ревью: пересечение четырёх множителей не ломает «агент = прокси», а сужает до минимума участников; гейт режет инъекционные векторы у корня |
