# Судейские вердикты: m1-apply пачка D (оркестратор)

> Ревью: M3 (1 high + 4 medium + 7 low + 3 nit, REJECT), GLM-Flash (0 blocker + 4 minor + 4 nit, отклонения приняты), Mercury (1 HIGH + 2 MEDIUM + 1 LOW + 2 INFO). Консенсус по heartbeat-дефекту — 2/3 (M3 high, Mercury high).

## Принято (гейтит аппрув)

| # | Находка | Решение |
|---|---|---|
| D-J-1 | Heartbeat `SessionLockManager.HeldLock.heartbeat()`: исключение гасит последующие тики (ScheduledExecutor их подавляет) → лок молча истекает; `close()` безусловно `unlock()` → «зомби» снимает лок нового владельца (M3 high, Mercury #1) | Ловить `Throwable` в heartbeat: логировать + помечать лок потерянным (`lost`), прекращать heartbeat; `close()` при `lost` — **не** вызывать `unlock()`; тест «сбой extend → лок помечен потерянным, чужой лок не снят» |
| D-J-2 | Потребление батча: `finishTurn` безусловно `last_consumed_seq := last_seq` — глотает USER-события, дописанные между последним рендером и завершением (окно отмены / микро-окно finish) (M3 #2, GLM D-1/D-2) | Реализовать **D-45**: потребление = watermark виденного (`max seq, вошедший в отрендеренный контекст`), едино для COMPLETED/FAILED/CANCELLED. Тесты: (а) USER-допись во время Turn'а → подхватывается доп. раундом (есть) либо остаётся непотреблённой и поднимает новый Turn; (б) USER-допись в окне отмены **не теряется** — новый Turn стартует; (в) FAILED не даёт retry-шторма (батч потреблён) |
| D-J-3 | Нарушение порядка сообщений OpenAI-протокола: при interleaved USER получается `AssistantMessage(tool_calls) → UserMessage → ToolResponseMessage`; strict-провайдер вернёт 400 (M3 #3, критично; WireMock не валидирует) | Исправить `SessionPromptBuilder`: tool-ответы строго сразу за ассистентом с соответствующими `tool_call_id`; межходовое USER-событие — ПОСЛЕ группы tool-ответов (следующим сообщением), порядок не должен ломаться ни при каком интерливинге; тест, проверяющий фактический порядок ролей/пар (не только успех вызова) |
| D-J-4 | `stop` не прерывает LLM-стрим: `blockLast` без `dispose` — Turn дочитывает генерацию (до таймаута), хотя Flux отменяем с пачки C (GLM D-3) | Отмена Turn'а диспозит подписку LLM-стрима; тест: stop во время стрима завершает Turn быстро (без дочитывания) |
| D-J-5 | `InMemorySessionEventBroadcaster.lastDeliveredSeq` теряется при рестарте (M3 #4) | Явно зафиксировать: broadcaster — in-memory, восстановление потока при реконнекте — из `SessionStore` по `since` (контракт SSE 8.5); убрать/пометить `lastDeliveredSeq` как не-источник-истины; тест-заготовка не обязателен, требование — запись в apply-notes |
| D-J-6 | `PollWakeJob` чистка `sess-*`: сравнение `lock_until < now()` с временем из JVM (TZ-риск) → возможна очистка живого продлённого лока (M3 #5, Mercury #3) | Сравнение строго в БД (SQL `now()`/`usingDbTime`-семантика), без Java-параметра времени; тест с несоответствием TZ сессии (или проверка текста запроса) |

## Отклонено

| # | Находка | Обоснование |
|---|---|---|
| D-R-1 | Mercury #2: «ошибка инструмента должна завершать Turn FAILED» | Противоречит спекам `workspace-tools`/`agent-turn`: `ERROR`/`LOST` TOOL_RESULT — **результат**, который видит модель и решает дальше (write-ahead + первый финальный результат). Turn FAILED — только исчерпание LLM-ретраев (9.2/§3 execution-model) |
| D-R-2 | `SimpleLock.extend()` вместо `LockExtender`; EVENT-хук = контракт `tryStart`; kill -9 пост-фактум (гейт 10.3); default-метод `WorkspaceTools` | Приняты оба ревьюера (GLM явно, M3 в кросс-чеке по 2/3): обоснования корректны, границы фаз соблюдены; вайринг `tryStart` в эндпоинт сообщений — задача 8.3 (пачка E) |
