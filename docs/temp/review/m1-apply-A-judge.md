# Судейские вердикты: m1-apply пачка A (оркестратор)

> После ревью (GLM: 2M/5m/5n; DS: 0b/3M/6m/4n) и кросс-чека.

## Принято (фикс разработчиком)

| # | Находка | Решение |
|---|---|---|
| A-J-1 | Hikari: ручная сборка не биндит `spring.datasource.hikari.*` (GLM M-1 + DS major, консенсус) | Исправить: применять hikari-* свойства к пула (через `DataSourceProperties` + явный bind HikariConfig), тест на применение ключа |
| A-J-2 | Jackson 2 в classpath: происхождение — прямая `jackson-datatype-jsr310` + `openai-java-core`, НЕ docker-java (DS; GLM согласна) | Убрать прямую J2-зависимость `jackson-datatype-jsr310` (JSR-310 есть в Jackson 3 из Boot 4); комментарий-мотивацию исправить; пин `Jackson3JsonFormatMapper` остаётся |
| A-J-3 | OSIV не отключён (GLM, кросс-чек) | `spring.jpa.open-in-view: false` в application.yml |
| A-J-4 | Каскады owner-FK vs конвенция data-model:4 «удаления каскадные от владельца» (DS#6, подтверждено в кросс-чеке) | `ON DELETE CASCADE` на `owner_user_id`-FK (app_user→session/task); llm/agent-FK остаются restrictive (Retention бессрочен, ссылки иммутабельны); пользователя всё равно не удаляем — конвенция ради единообразия |
| A-J-5 | Тест Jackson-маппера тавтологичен (DS#4, GLM приняла) | Усилить: тест фиксирует свойство `hibernate.type.json_format_mapper` = Jackson3-маппер (не только roundtrip) |
| A-J-6 | DS-миноры фактических расхождений миграции с data-model (FK `session.task_id` deferrable, тип `session_message.id`) | Разработчику сверить пункт за пунктом с data-model.md §5 и выровнять; расхождения без причины не допускаются |

## Отклонено

| # | Находка | Обоснование |
|---|---|---|
| A-R-1 | GLM A-1 major «поведенческий append-only тест» | Формулировка задачи 2.2 — «на уровне приложения»: reflection-guard контрактного API корректен; дублирование БД-гварда не требуется |
| A-R-2 | GLM A-2 major «UUIDv7 немонотонность в 1 мс» | Код владельца — директива, не трогаем;imestamp-сортируемость покрыта тестом; строго-монотонная гарантия для UUIDv7 нигде не требуется (монотонность — требование ULID, он из ulid-creator). Зафиксировать контракт в Javadoc IdGenerator |
| A-R-3 | DS major «preliquibase-хук не материализован» | По кросс-чеку снижено обеими сторонами: starter 2.0.0 несёт встроенные PG-скрипты, в Testcontainers-тестах хук ожидаемо no-op (БД создаёт контейнер). Хук подключён стартером; задача выполнена |
| A-R-4 | DS N-3 «cpu-nanos требует пересчёта» | Сам опровергнут в кросс-чеке: docker-java имеет `nanoCPUs` |
| A-R-5 | DS «имена индексов/конвенции» (косметика) | Конвенция `fk_/uidx_/ck_` последовательна; переименование — шум |
