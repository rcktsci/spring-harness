# Судейские вердикты: m1-apply пачка C (оркестратор)

> Ревью: M3 (1M + 6m + 13n, REJECT) и GLM-Flash (1M + 3m + 6n). Обе стороны сошлись на OOM-дефекте; кросс-спор только в severity (GLM: minor, M3: major) — принят как **major** (последствие: OOM всего оркестратора = падение всех сессий).

## Принято (гейтит аппрув)

| # | Находка | Решение |
|---|---|---|
| C-J-1 | OOM: `WorkspaceContainerManager.exec` копит stdout/stderr в `ByteArrayOutputStream` без ограничения, лимит `tool-output` применяется post-hoc (M3 #1 major, GLM C-1 major) | **Bounded capture** прямо в manager: чтение прерывается при превышении лимита (конфиг) + запас; процесс/exec не оставлять работать «в пустоту» (kill по достижении предела ИЛИ дренаж без накопления); тест: `yes`/большой вывод не приводит к росту памяти, результат `truncated` |
| C-J-2 | Mid-stream retry дублирует доставленные deltas (`LlmInvoker.stream` — `Retry.backoff` на всём `Flux.defer`) (M3 #2, GLM C-2) | Ретраить только до первого доставленного элемента; после начала стрима обрыв = FAILED (или явный новый раунд) — без повтора префикса; тест на mid-stream 5xx |
| C-J-3 | Полусозданный контейнер кэшируется как LOST навсегда: успешный `createContainerCmd` + падение `start`/`awaitRunning` оставляет контейнер в Docker, `findContainerId(showAll=true)` находит stopped и кэширует его (M3 #3, 2/3) | При падении старта — удалить контейнер; не кэшировать не-работающий; `ensureContainer` при остановленном контейнере — пересоздать (или удалить+создать), не отдавать LOST навсегда; тест |
| C-J-4 | `params_jsonb` маппится выборочно — `reasoning_effort` (пример из data-model §2) молча теряется (GLM C-3) | Пробрасывать параметры модели в options; неизвестные ключи — warning-лог (не молча) |
| C-J-5 | Хардкод `60_000` (M3 #6) | В конфиг (правило владельца) |
| C-J-6 | Прочие осмысленные minor/nit из обоих файлов: M3 #4 (exit≥128 — обработка), #5 (NUL/Pattern не ERROR), #7 (`OpenAIIoException` → transient) | Разработчику разобрать по файлам ревью; спорное — с обоснованием пропустить |
