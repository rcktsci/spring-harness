# Судейские вердикты: m1-apply пачка B (оркестратор)

> После ревью (GLM: 1b/0M/2m/4n; DS: 0b/1M/6m/6n) и кросс-факт-проверки оркестратора.

## Эксперимент оркестратора

`mvn test -Dtest=JwtSecurityTest` на JDK 25 (реальный Tomcat, живые HTTP-запросы): **7/7 зелёных**, включая `tokenOutsideAllowedGroupsReturns401` (401 + `code: unauthenticated`). GLM B-1 («500 вместо 401, тесты красные») — **опровергнут прямым экспериментом**; статическая модель порядка фильтров не описывает фактическую обработку исключения фреймворком.

## Принято (фикс разработчиком)

| # | Находка | Решение |
|---|---|---|
| B-J-1 | GLM B-2 + DS#2 (консенсус): безусловный UPSERT `app_user` на каждом запросе — write amplification | `ON CONFLICT … DO UPDATE … WHERE … IS DISTINCT FROM EXCLUDED.*` — запись только при изменении |
| B-J-2 | GLM B-3: `allowedGroups=null` → NPE → 500 в рантайме | Валидация `@NotEmpty` на `SecurityProperties.allowed-groups` — падение на старте, не в запросе |
| B-J-3 | DS#1 (major): `renderVisible` материализует Set каждого seq + `NOT IN :covered` — O(range) heap, риск лимита bind-параметров PG (~65535) при широких COMPACT | Переписать на диапазонную логику: лёгкая проекция (seq, kind) → in-memory определение видимости по диапазонам `covers` (без материализации Set всех seq) → выборка payload только видимых (условие по seq через диапазоны/пороги, не NOT IN со списком) |
| B-J-4 | DS#3: `covers` сужен до `{"from","to"}` (seq) при каноне «id/диапазоны» | Оставить seq-диапазоны (дешевле и достаточно M1); зафиксировать решением D-44 в `decisions.md` (сделает оркестратор); в Javadoc SessionStore — ссылка на D-44 |
| B-J-5 | DS: нет теста атомарности «резерв seq ↔ INSERT» при откате | Добавить тест: допись падает (например, некорректный kind/ограничение) → seq не «съеден», следующая допись получает seq без дыры |
| B-J-6 | DS: `AppUserSyncTest` мутирует общего Keycloak-пользователя без восстановления (порядкозависимость) | Изолировать: уникальные пользователи на тест (или восстановление) |
| B-J-7 | GLM/DS миноры-nit из файлов ревью, не противоречащие правилам | Разработчику разобрать `m1-apply-B-glm.md`/`m1-apply-B-deepseek.md` и закрыть дешёвые (осмысленные) пункты, спорные — не трогать |

## Отклонено

| # | Находка | Обоснование |
|---|---|---|
| B-R-1 | GLM B-1 (blocker): «500 вместо 401, тесты статически красные» | Опровергнуто экспериментом на реальном сервере (7/7, 401+PD); поведение залочено поведенческими тестами. Разработчику: добавить 1-строчный комментарий в SecurityConfig о механизме (обработка на error-dispatch), чтобы вопрос не всплывал |
| B-R-2 | DS «фильтры не в правильном порядке»-производные | Следствие B-R-1: фактический порядок работает и протестирован |
